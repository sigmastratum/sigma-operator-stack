# Community alpha launch operations

SOS adds no telemetry. Launch observations use public GitHub/package surfaces
and voluntary content-safe reports only.

## Ownership and checkpoints

The public launch owner for the first Community alpha is `@sigmastratum`.
That owner records and reviews:

- `D+2`: package, installation and support integrity;
- `D+7`: independent completion and the first actionable friction;
- `D+14`: retained installations, reproducible issues and contributions;
- `D+30`: a distinct second SOS event, referrals and repeated team pull.

Dates are measured from the first installable Community alpha publication,
not from source-preview visibility. A missed checkpoint is recorded as unknown,
not silently treated as success.

## Product evidence

The following may support a product-use statement when voluntarily and
content-safely reported:

- supported-path installation or initialization completed;
- qualification or fresh-session recovery completed;
- stale-source refusal observed;
- a distinct second SOS event in the same repository within 30 days;
- a reproducible external issue or accepted external contribution;
- an unaffiliated developer explanation or referral.

Repository views, clones, stars, forks and download counts are reach metrics,
not adoption. They are not active users or retained use. Unknown denominators are
not combined, and private tester messages are not published without permission.

## Pinned scope issue

After public visibility, create one issue from
[`alpha-scope-issue.md`](alpha-scope-issue.md), assign it to the launch owner and
pin it. Creating or pinning the issue is a separate remote action; this source
file grants no such authority.
